# Waypoint 제품 로드맵
작성: 2026-10-01 · 상위 카드: TRK-9

## 등록 상태
2026-10-01 등록 완료. 상위 TRK-9 아래 하위 12개(TRK-10~TRK-21)의 연결을 card_get으로 확인했다.
TRK-10~15는 다음 할 일, TRK-16~21은 조건부 아이디어다. 첫 실행 카드는 TRK-10이다.
[PRODUCT_ROADMAP_CARDS.json](PRODUCT_ROADMAP_CARDS.json)에 실제 ID·선행 카드·등록 인자를 보관한다. 다시 실행할 때 등록된 카드를 중복 생성하지 않는다.

## 제품의 승리 조건
Claude Code·Codex로 여러 프로젝트를 만드는 Mac 개인 개발자를 첫 고객으로 삼는다. 사용자가 별도로 기록을 정리하거나 맥락을 반복 설명하는 시간을 줄이고, 어디까지 검증됐는지 확인하도록 돕는다.
핵심 경험은 작업 발생 → 정확한 기록 → 중단 → 도구를 바꿔 재개 → 근거를 보고 완료 판단이다.
현재는 프로젝트 귀속·상태 표시·연동 진단·활동·재개 문맥 복사까지 구현했다. 자동 실행, 외부 사용자의 반복 사용, 유료 수요는 아직 입증되지 않았다.

Jira도 AI 코딩 에이전트·MCP 연결과 개발 맥락을 제품 방향으로 제시하고 있다. 연동 자체를 독점적 차별점으로 주장하지 않는다. 일부 소개 기능에는 대기 목록이 있으므로 실제 비교에서는 사용 가능한 버전·플랜·설정 범위를 기록한다.
- [Jira 개발자 제품 소개](https://www.atlassian.com/software/jira/dev)
- [Atlassian Rovo MCP 공식 문서](https://developer.atlassian.com/cloud/rovo-mcp/)
위 자료는 2026-10-01 확인. Waypoint의 우위는 아직 가설이다. 아래 숫자는 이미 달성한 결과나 시장 평균이 아니라 내부 의사결정 목표다.

| B. 외부 사람이 설치하고 사용 | TRK-13~15 | 10명 초기 사용 관찰, 2주 반복 사용과 동일 과제 비교 |

일정은 검증 관문으로 관리한다. 첫 카드 완료 때 실제 구현 속도로 다음 세 카드의 예상 기간을 갱신한다. 외부 참여자 모집·2주 관찰·4주 유료 관찰 시간을 개발 시간과 분리한다. 사용자 모집 전 날짜를 확정하거나 단기 출시를 약속하지 않는다.

## 측정 방법
- 핵심 지표: 주간에 이전 작업을 실제로 재개하고 검증 근거까지 확인한 사용자 수. 복사 버튼 클릭을 재개 성공으로 계산하지 않는다.
- 설치: 앱을 받은 시점부터 첫 실제 카드 연결까지. 처음 쓰는 10명 중 7명이 도움 없이 5분 이내 연결하는 것을 초기 목표로 한다.
- 재개: 고정된 중단 작업을 고른 시점부터 올바른 카드 연결과 첫 의미 있는 작업 행동까지. 준비·복사·연결 시각은 앱 기록으로, 실제 작업 재개는 관찰로 구분한다. 중앙값 60초 이내, 기존 방식 대비 50% 단축이 목표다.
- 반복 사용: 첫 연결을 마친 10명을 같은 코호트로 추적한다. 2주차 3일 이상 실제 작업/재개를 기록한 사용자 6명 목표. 중도 이탈을 분모에서 빼지 않는다.
- Jira 비교: 실제 Jira 사용자 하위집단에서 동일 난이도의 두 과제를 사용하고 수행 순서를 교차한다. Jira의 기존 연동도 사용하게 한다. 표본 수·분산·실패 원인을 함께 기록한다. 작은 표본으로 전체 시장 우위를 주장하지 않는다.
- 신뢰성: 정해진 재수신·다른 폴더·프로젝트 전환·도구 변경·복수 세션·잠자기·재시작 시나리오에서 기록 누락/중복/오귀속 0건. Mac 수신→저장/표시 p95 2초 목표는 지원 환경에서 측정하며 CloudKit 전달 시간을 섞지 않는다.
- 지불: 실제 유료 사용자 3명, 그중 4주 뒤 사용 중인 사용자 2명이 초기 파일럿 목표. 설문상 구매 의향은 실제 지불로 세지 않는다.
- 결과가 기준에 못 미치면 세션 관찰과 인터뷰로 가장 큰 원인을 고치고 같은 기준으로 다시 측정한다. 기능 개수로 실패를 덮지 않는다.
- 측정은 로컬 우선. 진단 내보내기는 사용자가 선택하고, 대화·소스 원문을 기본 수집/전송하지 않는다.

## 이후 작업 선택 규칙
1. 사용자가 개발을 이어가라고 하면 이 문서와 TRK-9 하위 카드부터 읽는다. 매번 “다음 무엇을 할까요?”를 묻지 않는다.
2. 선행 조건을 충족한 가장 앞 번호의 미완료 실행 카드를 시작한다. 상위 TRK-9는 로드맵 묶음이며 자체를 첫 기능 작업으로 취급하지 않는다.
3. TRK-10~15는 확정된 다음 할 일이다. TRK-16~21는 조건부 아이디어로 보관하고 실제 관문 통과와 수요에 따라 다음 할 일로 승격한다. TRK-16~18 전부를 만드는 것이 유료 전환의 필수 조건은 아니다.
4. 반복되는 기록 손실·데이터 손상·오귀속은 기능 작업보다 먼저 처리한다.
5. 다른 카드와 독립적인 준비는 외부 검증 대기 중 진행할 수 있다. 참여자·관찰 결과·실제 지불이 없는 카드를 완료 처리하지 않는다.
6. 사용자 요청에 맞는 구현·검증·기록을 자율 진행한다. 실제 외부 초대 발송·과금·공개 출시는 해당 행동의 명시적 실행 지시가 있을 때 한다. 문서 준비만으로 발송·출시된 것으로 간주하지 않는다.
7. 각 카드의 검증 근거와 남은 문제를 남기고 다음 카드 ID를 인수인계 메모에 적는다. 이 문서는 백그라운드 자동 실행 스케줄러가 아니며 현재 요청은 계획·등록이다.

## 범위
Mac 우선, Claude Code·Codex 우선. 사용 중인 도구와 로컬 자료를 활용한다. 앱의 직접 LLM API 호출, 자동 완료, 자동 요약/분류는 현재 설계에 넣지 않는다.
초기 투자에서 모바일 새 기능·모든 AI 연결·대기업용 권한 체계·범용 스프린트/보고서·완전한 양방향 Jira 동기화를 제외한다. 필요성은 사용자 관찰로 재판단한다.
장기적 강점은 정확한 프로젝트 기록과 재개/검증 흐름의 완성도다. 데이터 내보내기는 제공하며 사용자의 기록을 묶어 두는 것을 경쟁력으로 삼지 않는다.

- 실제 카드 ID: TRK-16
- 선행: TRK-15

조건부 P1. 베타에서 다음 작업 선택의 어려움이 확인되면 승격한다. 사용자가 지정한 우선순위·카드 의존성·막힌 이유로 실행 가능한 일을 보여준다. 사용자 지정 규칙을 쓰며 LLM 자동 추천이나 임의 분류는 넣지 않는다.

완료 조건:

- [ ] 우선순위·선행 작업·막힘을 입력하고 오늘 진행 가능한 카드를 확인한다
- [ ] 순환 의존성·보관된 선행 작업·여러 프로젝트 우선순위 충돌을 처리한다
- [ ] 베타 사용자가 다음 작업을 고르는 시간을 전후 비교하고 실제 개선 여부를 기록한다

### TRK-17 · 여러 AI 동시 작업의 충돌과 소유 범위

- 예정 상태: 아이디어 · 관문 통과 후 승격
- 실제 카드 ID: TRK-17
- 선행: TRK-15

조건부 P1. 베타에서 동시 에이전트 사용자가 반복적인 충돌을 겪으면 승격한다. 카드별 세션·브랜치·worktree를 표시하고 관측된 같은 파일 변경의 겹침을 알린다. 알림은 충돌 가능성이며 실제 Git 충돌 확정과 구분한다. 자동 프로세스 종료·강제 잠금·파일 이동은 기본 범위 밖이다.

완료 조건:

- [ ] 카드별 저장소·브랜치·worktree·실행 세션을 구분한다
- [ ] 관측된 파일 겹침을 알려도 별도 worktree나 끝난 세션에 잘못 경고하지 않는다
- [ ] 동시 작업 재현 시나리오에서 경고의 근거·누락 범위·과도한 알림 빈도를 검증한다

### TRK-18 · 기존 업무 기록 연결 — GitHub·Jira·내보내기

- 예정 상태: 아이디어 · 관문 통과 후 승격
- 실제 카드 ID: TRK-18
- 선행: TRK-15

조건부 P1. 기존 이슈 관리 도구를 계속 쓰려는 베타 수요가 확인되면 승격한다. 우선 카드의 외부 이슈/PR 링크와 Markdown·JSON 내보내기를 제공한다. 다음으로 가장 많이 쓰는 한 서비스의 읽기 전용 가져오기만 지원한다. 양방향 상태 동기화는 별도 설계 후 결정한다.

완료 조건:

- [ ] 카드↔외부 이슈/PR 출처를 보존하고 휴대 가능한 형식으로 내보낸다
- [ ] 가져오기 재시도·중복·권한 상실·외부 삭제를 처리한다
- [ ] 외부 티켓 완료가 Waypoint 카드를 의도 없이 완료시키지 않는다
- [ ] 실제 사용자에게 이중 입력이 줄었는지 확인한다

### TRK-19 · 유료 개인판 제안과 반복 문제 해결

- 예정 상태: 아이디어 · 관문 통과 후 승격
- 실제 카드 ID: TRK-19
- 선행: TRK-15

조건부 P1. 베타 결과가 진행 기준에 도달하면 승격하고, 미달 시 원인 수정·재측정을 먼저 한다. 핵심 가치가 드러나는 실제 데모·제품 설명·체험 흐름과 가격 가설을 만든다. TRK-16~18는 관측된 문제에 필요한 것만 선행한다. 추정 가격을 시장 사실로 취급하지 않는다.

완료 조건:

- [ ] 베타에서 확인된 상위 3개 반복 문제를 해결하고 재평가한다
- [ ] 근거 있는 전후 데모·대상 사용자·지원 범위·알려진 제한을 담은 판매 초안을 준비한다
- [ ] 실제 대상자 5명 이상의 가격 반응과 유료 전환 거절 이유를 기록한다
- [ ] 유료 파일럿의 가격·체험 기간·지원 범위를 근거와 함께 결정한다

### TRK-20 · 유료 파일럿 — 결제·라이선스·지속 사용

- 예정 상태: 아이디어 · 관문 통과 후 승격
- 실제 카드 ID: TRK-20
- 선행: TRK-14, TRK-19

조건부 P1. 유료 제안 검증 뒤 진행한다. 결제/라이선스/업데이트/오프라인 사용·실패 복구의 최소 흐름을 준비한다. 과금과 공개 출시는 검증된 설정 및 별도 출시 지시가 있어야 실행한다. 핵심 기록 열람·내보내기를 구독 만료로 막지 않는 원칙을 설계한다.

완료 조건:

- [ ] 테스트 환경에서 결제·취소·라이선스 복구·업데이트·오프라인 동작을 검증한다
- [ ] 실제 유료 고객 3명 이상과 4주 후 계속 사용하는 고객 2명 이상을 초기 목표로 결과를 기록한다
- [ ] 지원 부담·지불 이유·이탈 원인을 기록하고 지속 개발 가능한지 판단한다

### TRK-21 · 소규모 팀 확장 타당성 — 공유·권한·인수인계

- 예정 상태: 아이디어 · 관문 통과 후 승격
- 실제 카드 ID: TRK-21
- 선행: TRK-20

조건부 P2. 개인판 반복 사용·실제 지불과 팀 공유 수요가 확인될 때 착수한다. 2~5인 팀의 공유 카드·담당 범위·검증 근거·인수인계를 검증한다. 개인 CloudKit 동기화를 팀 협업으로 간주하지 않는다. 계정·권한·충돌·감사 이력의 저장 구조를 먼저 결정한다. 범용 기업용 Jira 복제는 범위 밖이다.

완료 조건:

- [ ] 최소 2개 팀의 구체적 공유 요구와 현재 손실을 확인한다
- [ ] 공유 데이터·개인 기록·권한 경계와 저장 구조의 설계/비용을 비교한다
- [ ] 격리된 프로토타입으로 접근 권한·동시 수정·사용자 탈퇴·감사 기록을 검증한다
- [ ] 팀 파일럿 결과로 정식 팀판 투자 여부를 결정한다

## 2026-10-02 재검토 — Jira의 기능을 담기

Jira는 2026년 5월 작업 항목을 AI 에이전트에게 배정하는 기능을 정식 출시했고(Rovo Dev·외부 코딩 에이전트), Linear도 이슈에서 Claude Code·Codex 세션을 돌린다. 경쟁 도구는 「티켓에서 출발해 클라우드 에이전트에 맡기기」로 간다.

방향(사용자 결정): **Jira 연동은 하지 않는다. Jira가 하는 일을 Waypoint 안에 담되, 사람이 입력하는 대신 에이전트 기록으로 저절로 채운다.** 처음 이 재검토에서 Jira 연동(TRK-18·50~52)을 1순위로 잡았다가 사용자 지시로 취소·보관했다.

| 순위 | 카드 | Jira 기능 | Waypoint 방식 |
|---|---|---|---|
| 1 | TRK-16 계획 | 우선순위·마감일·선행·막힘·백로그 | 사람 입력은 최소, 막힘은 관계에서, 진행은 근거에서 계산. 오늘 할 일 보기 |
| 2 | TRK-58 마일스톤 | 릴리스·에픽 묶음 | 목표일과 묶인 카드, 근거 기반 진행률 |
| 3 | TRK-59 카드 관계와 라벨 | 이슈 링크·라벨 | 에이전트도 MCP로 건다 |
| 4 | TRK-60 검색·필터·저장된 보기 | JQL·필터 | 프로젝트를 가로지르는 필터와 저장된 보기 |
| 5 | TRK-54 기록 기반 보고서 | 처리 시간·진행 보고 | 입력 없이 실제 세션·근거로 |
| 6 | TRK-61 알림 | 알림 | 풀린 막힘·오래 멈춤·마감 |
| 유지 | TRK-17 동시 작업 충돌 | (Jira에 없음) | 세션별 바뀐 파일로 겹침 경고 |
| 유지 | TRK-53 원격·클라우드 세션 수집 | — | 「다 기록된다」 약속의 사각지대 |
| 기본기 | TRK-55 로그인 때 자동 실행, TRK-56 자동 업데이트 | — | 베타 2주의 공백·빌드 전달 |
| 결정 대기 | TRK-57 카드에서 에이전트 작업 맡기기 | 에이전트 배정 | 「앱은 작업을 자동 실행하지 않는다」 원칙 변경 필요 |

하지 않는 것: Jira 연동, 사용자 정의 워크플로(고정 상태 열 유지), 팀 공유·권한(TRK-21, 개인판 검증 뒤). TRK-16·58·59는 저장 형식 2판 하나에 필드를 함께 담는다(1판 얼리기 초안은 로컬 브랜치 `schema-v1-freeze-draft`).
