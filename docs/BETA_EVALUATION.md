# 외부 사용자 평가 절차 — 설치와 첫 연결

작성: 2026-10-02 · 카드: TRK-45(준비), TRK-15(실행) · 기준: [PRODUCT_ROADMAP.md](PRODUCT_ROADMAP.md) 「측정 방법」

이 문서는 준비물이다. 모집 문구 발송, 참여자 연락, 보상 지급은 하지 않았고, 사용자가 실행을 명시적으로 지시할 때만 한다. 문서가 있다고 평가가 시작된 것으로 보지 않는다.

## 1. 무엇을 확인하나

| 질문 | 목표(내부 의사결정용) | 재는 법 |
|---|---|---|
| 처음 쓰는 사람이 도움 없이 연결하나 | 10명 중 7명이 5분 안에 첫 카드 연결 | 앱 첫 연결 지표([RELIABILITY.md](RELIABILITY.md) 「첫 연결 지표」) + 관찰자 기록 |
| 어디서 멈추나 | 가장 많이 멈춘 단계와 까닭 상위 3개 | 지표의 실패 지점 + 관찰 메모 |
| 2주 뒤에도 쓰나(TRK-15) | 2주차 3일 이상 실제 작업·재개 기록 6/10 | 참여자가 고른 날의 진단 정보 + 인터뷰 |

목표는 가설이다. 결과가 못 미치면 가장 큰 원인을 고치고 같은 절차로 다시 잰다. 작은 표본으로 일반적인 우위를 주장하지 않는다.

## 2. 참여자

- 대상: Mac에서 Claude Code나 Codex로 둘 이상의 프로젝트를 오가며 작업하는 개인 개발자.
- 인원: 10명. Claude Code만, Codex만, 둘 다 쓰는 사람이 섞이게 한다. Jira를 실제로 쓰는 사람은 따로 표시한다(TRK-15 비교용).
- 제외: Waypoint 개발에 참여한 사람, 설치 과정을 미리 본 사람.
- 지원 환경: macOS 14 이상, Claude Code·Codex는 참여 시점의 최신판. 참여자마다 버전을 적는다.

### 모집 문구 초안(발송하지 않음)

> Claude Code나 Codex로 여러 프로젝트를 동시에 진행하는 Mac 개발자를 찾습니다.
> 프로젝트별로 AI 작업 흐름을 카드로 정리해 주는 Mac 앱을 시험하고 있습니다. 처음 설치부터 첫 작업이 기록되기까지 30분 정도 화면 공유로 함께해 주시면 됩니다.
> 앱은 AI 서비스를 따로 호출하지 않고, 대화 원문은 내 Mac 밖으로 보내지 않습니다. 기록은 언제든 지울 수 있습니다.
> 관심 있으시면 쓰는 도구(Claude Code·Codex)와 동시에 진행 중인 프로젝트 수를 알려 주세요.

## 3. 세션 진행(30분, 화면 공유)

| 시간 | 할 일 | 관찰자 |
|---|---|---|
| 0–3분 | 동의 확인(아래 4절), 도구 버전 기록 | 질문에만 답하고 화면 조작 방법은 알려 주지 않는다 |
| 3–13분 | **과제 1** 앱을 열고 평소 쓰는 도구를 연결한다 | 시작 시각 = 앱을 처음 연 순간. 멈춘 곳·망설인 곳을 시각과 함께 적는다 |
| 13–20분 | **과제 2** 지금 진행 중인 프로젝트 하나를 등록하고, 그 폴더에서 평소처럼 작업 하나를 시작한다 | 첫 카드 연결 시각 = 앱에 그 작업이 처음 보인 순간 |
| 20–25분 | **과제 3** 앱에서 방금 작업이 어디까지 왔는지 찾아 말해 본다 | 찾는 데 걸린 시간, 틀리게 읽은 것 |
| 25–30분 | 인터뷰(5절), 진단 정보 받기(6절) | — |

- 도움 기준: 참여자가 막혀 3분이 지나거나 직접 도움을 청하면 도와준다. 도운 시각과 내용을 적고, 그 참여자는 「도움 없이 연결」에서 뺀다.
- 실패로 끝나도 세션을 계속하고 원인을 적는다. 중도 이탈자도 분모에 남긴다.

## 4. 동의와 데이터

- 세션 전에 말로 확인한다: 화면 공유 기록 여부, 진단 정보 공유 여부, 결과를 이름 없이 요약해 쓴다는 것.
- 받는 것: 앱의 「진단 정보 복사」 텍스트(버전·연결 상태·수신 시각·숫자 지표. 대화·프롬프트·파일 경로는 들어 있지 않다)와 관찰 메모.
- 받지 않는 것: 대화 원문, 소스 코드, 프로젝트 이름과 경로. 화면 공유에 나온 내용은 메모로 옮기지 않는다.
- 참여자가 원하면 기록과 앱을 지우는 방법을 세션 끝에 같이 확인한다.

## 5. 인터뷰 질문

1. 연결하다 가장 헷갈린 순간은 언제였나요? 그때 무엇을 기대했나요?
2. 지금은 여러 프로젝트의 AI 작업을 어떻게 기억하고 이어가나요?
3. 오늘 본 화면 중 다시 열어 볼 것 같은 곳과 그 이유는요?
4. 2주 동안 써 본다면 무엇이 있어야 계속 쓰게 될까요? 무엇이 있으면 지우게 될까요?

## 7. 정리

- 10명이 끝나면 표 하나로 모은다: 참여자별 걸린 시간·도움 여부·멈춘 단계·도구 버전.
- 앱 지표는 온보딩을 연 순간부터 잰다. 관찰은 앱을 처음 연 순간부터 잰다. 둘의 차이(앱을 받고 열기까지)는 관찰 기록으로만 안다.
- 앱 지표와 관찰이 다르면 둘 다 적고 차이의 원인을 찾는다. 앱 지표만으로 성공을 세지 않는다.
- 멈춘 원인 상위 3개를 카드로 만들고, 고친 뒤 같은 절차로 다시 잴지 결정한다.
- 2주 반복 사용·재개 시간·Jira 비교는 TRK-15에서 이 절차에 이어 진행한다.
