# 결정 기록

왜 이렇게 정했는지만 남긴다. 동작 명세는 `docs/SPEC.md`에 있다.
항목은 **결정** · 이유 · (버린 대안). 절 제목 끝에 카드 번호와 날짜를 적는다. 뒤집힌 결정은 이긴 쪽만 남기고 「뒤집음」으로 표시한다.

## 바탕

- **평소용(Release, 47821)과 개발용 Waypoint Dev(Debug, 47822)를 번들 ID로 나눈다.** 개발 중 앱을 껐다 켜면 다른 저장소 추적이 끊기고 실측 기록이 실제 기록에 섞였다. (실행 인자로 고르기: 같은 번들 ID라 동시 실행·로그인 항목이 섞인다)
- **실측 폴더는 폴더 안 설정(`.claude/settings.local.json`, `.mcp.json`)만 Dev로 돌린다.** 전역 설정을 바꾸면 평소 추적이 끊긴다. 프로젝트 범위 MCP가 사용자 범위보다 먼저 읽힌다.
- **외부 Swift 패키지를 쓰지 않는다. MCP는 필요한 부분만 직접 구현했다.** 예외는 Sparkle(아래 배포 절).
- **앱 아이콘은 이정표(후보 1), Dev는 검은 바탕.** 사용자 선택. 두 인스턴스를 Dock에서 가려 본다.

## 훅 수신과 세션 (09-28 ~ 10-01)

- **서브에이전트 세션 ID는 훅의 `agent_id`.** 서브에이전트 안의 훅은 `session_id`가 부모와 같다.
- **서브에이전트 세션은 `SubagentStart`에서 만들고, 직전 `PreToolUse(Agent)` 프롬프트의 카드 ID를 같은 에이전트 종류의 가장 오래된 대기 항목과 짝짓는다(10분).** 두 이벤트를 잇는 키가 없다. 틀린 카드에 붙이느니 안 붙인다. (`prompt_id`로 잇기: 한 턴에 여럿이면 구분 못 함)
- **카드 ID가 없는 서브에이전트는 카드에 붙이지 않고, 파일 변경만 부모 세션의 작업중 카드에 남긴다.** 카드 연결은 명시적일 때만, 파일 기록은 잃지 않게.
- **`SessionStart` 없이 다른 훅이 먼저 와도 등록 폴더면 세션을 만든다. 끝난 세션은 끝난 시각 뒤의 훅만 되살린다.** 훅을 세션 중간에 등록하는 경우를 받고, outbox로 늦게 온 기록이 끝난 세션을 되살리지 않게.
- **카드 없는 세션의 파일 변경·커밋도 프로젝트 이벤트로 남긴다.** 기록을 버리지 않는다.
- **줄 수는 `structuredPatch`·`bashEditDiff` 조각에서, 커밋은 `gitOperation.commit`에서 읽는다. 없으면 입력 추정.** 입력 추정은 `replace_all`·덮어쓰기에서 틀리고, 명령 문자열 검사는 별칭·스크립트 커밋을 놓친다. 입력 추정만 쓰던 처음 방식을 뒤집음.
- **git 브랜치·체크아웃·origin은 `.git` 파일을 직접 읽는다.** 훅 처리 안에서 git 프로세스를 띄우지 않는다.
- **로컬 서버는 127.0.0.1에만 열고 요청당 5초·본문 1 MiB로 제한한다.** 외부 접속 차단, 멈춘 연결 정리.
- **훅 스크립트 curl에 `--noproxy '*'`.** 셸에 `http_proxy`가 있으면 루프백 요청이 프록시로 간다.
- **세션의 프로젝트는 옮기지 않는다. 시작 폴더와 다른 프로젝트에서 일하면 `session_bind`와 변경 파일 경로로 귀속한다(09-30).** 세션을 옮기면 카드 연결·서브에이전트·이벤트 소유가 함께 걸리고, 잠깐 `cd`한 것만으로 프로젝트가 뒤집힌다. 다른 프로젝트 파일은 지금 카드에 붙이지 않는다.
- **커밋·검증의 프로젝트는 도구 입력 폴더 → 훅 `cwd`의 등록 프로젝트 → 세션 프로젝트 순(TRK-11).** 훅 `cwd`는 `cd`를 따라가서, 다른 프로젝트에서 한 커밋이 시작 프로젝트 카드에 붙었다.
- **재수신은 `tool_use_id`·`prompt_id`/`turn_id`로 거른다(TRK-11).** 응답이 1초를 넘으면 같은 훅이 outbox에도 쓰여 중복·오귀속이 생겼다. (시각·내용 비교: 같은 수정을 두 번 하면 잃는다)
- **끝난 세션보다 이른 늦은 `PostToolUse`는 버린다(TRK-11).** 같은 ID 세션이 하나 더 생겼고, 그 기록은 실시간으로 이미 받았다.
- **작업 상태는 이벤트로 가른다: 도구 작업·응답 진행·입력 대기·승인 대기·활동 없음·추적 만료·종료(09-30).** 시간만으로 「멈춤」을 단정하면 긴 도구 작업과 입력 대기를 잘못 판정한다. 병렬 도구는 호출 ID별로 닫는다.
- **저장 알림과 로컬 요청 처리를 화면 갱신에 잇고, 경과 확인은 5초·종료 점검은 10초(09-30).** 30초 TimelineView만 기다리던 처음 방식을 뒤집음.

## 세션 종료 판정 (09-28 ~ 09-30)

- **훅 스크립트가 Claude Code PID를 보내고, 앱이 주기적으로 프로세스가 없는 메인 세션을 끝낸다.** `SessionEnd`가 빠지는 세션이 있어 멈춤으로 영원히 남았다. 프로세스 유무가 가장 직접적이다. (전사 파일 시각: 오래 입력을 기다리면 오판)
- **PID를 모르는 세션은 30분 활동 유효기간으로 끝낸다(09-30).** 처음의 24시간 규칙을 뒤집음. 자동 정리는 기록을 지우거나 카드를 완료하지 않는다.
- **PID는 더 새 훅이 다른 PID를 가져오면 바꾸고, 재사용 검사는 프로세스 시작 시각을 `lastSeenAt`과 비교한다.** `--resume`은 같은 세션 ID를 새 프로세스로 잇는다. 마지막 훅 뒤에 시작한 프로세스는 그 훅을 보냈을 수 없다.
- **PID는 실행 파일 경로로 찾는다.** 네이티브 설치의 프로세스 이름은 버전 번호라 이름으로 못 찾는다(09-30에 고침).
- **앱이 끝낸 세션의 `endedAt`은 검사 시각, `lastSeenAt`은 그대로.** 그 뒤 진짜 resume은 살리고 그 전 늦은 기록은 무시하는 규칙이 그대로 맞는다.
- **완료한 카드에서 떨어진 세션은 새 요청이나 실행 중인 하위 작업이 없으면 작업중 타일로 되살리지 않는다(09-30).**

## 시작 블록 주입 (09-28 ~ TRK-35)

- **블록을 받지 못한 메인 세션에는 다음 `UserPromptSubmit`에 한 번 더 준다.** 등록 전에 시작했거나 다른 폴더에서 온 세션은 블록이 없어 스킬이 카드를 붙이지 못했다. `SessionStart`와 같은 평문 stdout이라 스크립트가 단순하다.
- **outbox로 흡수한 훅은 블록을 만들지 않고 받았다고 적지 않는다.** 이미 지난 훅이라 대화에 들어가지 않았다.
- **블록은 스크립트의 확인(`POST /hooks/ack`)을 받아야 받은 것으로 적는다. 중복은 허용, 같은 블록은 3번까지(TRK-35).** 응답이 1초를 넘으면 스크립트는 출력하지 않는데 앱은 줬다고 적어 블록을 잃었다. 유실보다 중복이 낫다.
- **확인 요청은 서버 큐에서 바로 204로 받고, 확정은 그 세션의 다음 훅에서 한다(TRK-35).** 메인에서 저장하던 첫 구현은 훅 시간을 크게 늘렸다. (백그라운드 curl: 훅이 끝날 때 정리되는지 확인할 수 없다)
- **확인 머리가 없는 옛 스크립트는 예전처럼 바로 확정한다(TRK-35).** 앱과 스크립트를 어느 순서로 바꿔도 예전 동작으로 떨어진다.
- **직전 세션 메모는 가장 최근 `card_handoff`한 카드 하나, 마지막 줄에 스킬 안내.** 안내 줄이 스킬을 부르는 계기다(TRK-62에서 「단위를 끝낼 때마다」로 넓힘).

## outbox (09-28 ~ TRK-33)

- **outbox는 이름을 바꿔 떼어 낸 뒤 처리한다.** 흡수 중 새로 쓰는 줄을 잃지 않고, 도중에 죽어도 다음 실행에서 잇는다.
- **샘플 모드는 서버를 열지 않고 outbox도 흡수하지 않는다.** 메모리 저장소에 흡수하면 실제 기록을 잃는다.
- **outbox에는 앱이 읽는 필드만 jq 허용 목록으로 남긴다(10-01).** matcher를 `*`로 넓힌 뒤 파일 내용·명령 출력 원문이 쌓였다. 앱 코드는 그대로라 옛 앱도 읽는다.
- **저장에 실패하면 그 줄부터 끝까지 남기고 멈춘다(TRK-32).** 순서가 중요하고, 실패 원인은 대개 뒤 줄에도 걸린다. 읽을 수 없는 줄은 `outbox.quarantine.jsonl`에 원문 그대로.
- **흡수는 매번 새 `ModelContext`에서 하고, 실패하면 그 context를 버린 뒤 같은 실행에서 다시 흡수한다(TRK-33).** SwiftData `rollback()`은 이미 올라온 모델 값을 되돌리지 않아 같은 context로 다시 처리하면 빈 세션 ID·세션 없는 연결이 저장됐다. TRK-32의 「다음 실행 때만 재흡수」를 뒤집음.
- **흡수 뒤 메인 context의 프로젝트·카드·세션·연결을 다시 가져온다(TRK-33).** 다른 context의 저장은 올라온 객체에 저절로 들어오지 않고, 그 객체를 저장하면 옛 값이 덮는다. 흡수 전에 메인 context의 변경을 먼저 저장한다.

## 저장 실패 뒤 다시 읽기 (TRK-33·34)

- **「바꾸고 저장, 실패하면 rollback 뒤 다시 읽고 다시 던짐」을 `ContextReload.commit` 하나로 묶어 훅·정리·MCP·등록·보드·카드 상세가 쓴다.** rollback만 하면 실패한 값이 화면에 남고 다음 저장에 섞인다. 경로마다 두 줄을 쓰면 빠뜨린다.
- **MCP는 도구가 오류를 던진 경우에도 다시 읽는다.** 일부를 바꾼 뒤 던지면 저장 실패와 같다.
- **놓을 수 없는 칸·바꿀 것 없는 조건은 `commit` 전에 거른다.** 거절에도 rollback하면 다른 저장 안 된 변경을 버린다.

## MCP (09-28)

- **초기화 방식(2025 판들)만 받고, 모르는 버전 머리에는 본문 없는 400.** Claude Code는 새 방식을 먼저 떠보고 400이면 `initialize`로 내려온다. (두 방식 모두 지원: 구현이 크다)
- **`Mcp-Session-Id`는 주기만 하고 검사하지 않는다.** 세션별 상태가 없고, 검사하면 앱을 다시 켤 때마다 실행 중인 세션이 다시 초기화해야 한다.
- **도구 실패는 `isError: true` 결과로 주고 그 호출의 변경은 되돌린다.** Claude가 이유를 읽고 고쳐 부른다. 모르는 도구만 JSON-RPC 오류.
- **`card_start`는 그 세션의 다른 카드 연결을 먼저 푼다. done 카드도 시작할 수 있다.** 세션 하나는 주제 하나. 끝나면 done으로 돌아간다.
- **`card_create` 기본 상태는 kind가 idea면 idea, 나머지 next. `card_list` 기본은 done·archived를 뺀다.**
- **handoff·조건 체크는 `note` 이벤트의 `kind`로, 근거·상황·GitHub 기록은 새 이벤트 종류로 남긴다. 모델 필드는 늘리지 않는다.** 저장 형식·CloudKit 스키마가 그대로다. 옛 앱은 모르는 종류를 `note`로 읽으므로, 메모로 보이면 안 되는 payload에는 `text` 키를 두지 않는다.

## 카드와 보드 (09-28 ~ 09-29)

- **보드 칸 순서: 아이디어 최신순, 다음 번호순, 작업중 연결 시각순, 완료 최신순.** 다음 칸은 가장 예측 가능한 번호순. (수동 정렬: 순서 필드 필요)
- **작업중 카드를 다른 칸으로 끌어 놓는 것도 허용한다.** 드래그 중엔 끌고 있는 카드를 몰라 막으면 강조된 칸이 거절하는 꼴이 된다.
- **카드가 active를 떠나면 열린 세션 연결을 모두 닫는다. 상태 복귀는 하지 않는다.** 연결이 열린 채 남아 사이드바는 「멈춤 1」, 보드 작업중 칸은 빈 어긋남이 생겼다. 「move는 연결을 건드리지 않는다」를 뒤집음. (`statusBeforeActive`로 복귀: 사용자가 정한 새 상태를 덮는다)
- **작업중 카드의 경과는 카드에 연결된 시각부터.** 카드 화면이라 「이 카드를 얼마나 했나」가 맞다. 대시보드·iPhone 카드 줄도 같다.
- **보드 칸 최소 폭 220, 프로젝트 보드는 인스펙터를 닫은 채 시작한다(09-29).** 좁은 칸에서 제목이 4~5줄로 꺾였다. 더 좁은 창은 가로로 넘긴다. 200 → 165 → 220으로 두 번 바꿨다.
- **누적 작업의 서브에이전트 수는 카드에 붙은 메인 세션의 서브에이전트까지 센다.**
- **카드 정보는 기존 인스펙터 자리를 쓴다.** 본문 오른쪽에 칸을 더하면 인스펙터와 세 칸이 된다.
- **완료 조건을 다 채워도 상태는 그대로.** 자동 done 금지.
- **카드 본문 Markdown은 인라인 문법만.**
- **화면 문구에서 시안의 해석 문장(「대화에서 감지」 등)을 빼고 사실만 남긴다.**

## 카드 없는 세션 (09-28)

- **대시보드·보드·사이드바에서 카드 없는 메인 세션도 작업중으로 센다.** 카드 없이도 세션이 보여야 하고, 화면마다 숫자가 같아야 한다.
- **카드 없는 세션의 제목 자리는 마지막 사용자 요청 문장(300자), 경과는 그 요청부터.** 앱은 요약을 하지 않으므로 사용자 자신의 문장이 가장 알아보기 쉽다. 사용자 문장이 저장소와 개인 iCloud에 남는다. (첫 요청: 지금 일과 멀다, 전사 파일 읽기: 훅 밖 파일을 읽게 된다)
- **요청 문장에서 서브에이전트 훅·빈 문장·`<`로 시작하는 자동 메시지는 뺀다. `<pasted_content>`는 태그만 벗긴다.** 서브에이전트 완료 알림도 `UserPromptSubmit`으로 온다.

## 대시보드 상황판 (TRK-64, 10-02)

- **대시보드 아래 프로젝트 표를 상황판으로 바꾼다. 별도 화면은 늘리지 않는다.** 시안 없이 바로 구현(사용자 지시).

## 완료 근거 (TRK-10, 10-01)

- **카드 없는 세션의 검증 실행은 기록하지 않는다.**
- **검증 명령 패턴은 Swift 상수와 훅 스크립트에 같은 문자열로 두고 테스트로 비교한다.** 앱이 꺼진 동안의 검증도 outbox로 근거가 된다.

## 지침·기억 출처 (TRK-37~41, 10-01 ~ 10-02)

- **상위 폴더는 프로젝트의 부모부터 홈까지만 찾는다. 홈 자체는 감시하지 않는다.** 홈 전체 감시는 모든 파일 변경을 받는다.
- **기억 폴더는 등록 경로·링크를 푼 경로·git 뿌리 중 하나와 맞으면 그 프로젝트. 짝짓지 못한 폴더는 실제 폴더를 읽어 경로를 되찾는다.** 폴더 이름의 `-`가 원래 무엇이었는지 이름만으론 모른다.

- **항목 범위는 UTF-8 바이트 위치로 잡는다.** `String`은 `\r\n`을 한 글자로 보고 정규화 비교를 해서 바이트 차이를 놓친다.
- **줄 판정은 지침 문서 렌더러와 같은 함수를 쓴다.** 보기 화면과 항목 모양이 같아야 한다. `---`는 늘 구분선, 목록 안의 코드 울타리는 닫는 줄까지 그 항목.
- **여러 줄 HTML 주석과 UTF-8이 아닌 문서는 문서 전체 한 항목에 편집 금지. 한 줄짜리 주석은 항목 밖 줄(TRK-39).** 보수적으로. 한 줄 주석은 Next.js 갱신 표식이라 지침이 숨지 않는다.
- **항목을 지울 때 앞뒤 빈 줄은 하나까지만 같이 지운다.** 빈 줄이 쌓이지 않고 결과를 예측할 수 있다.
- **항목 보기·고치기는 시안 1 「항목 목록」(TRK-40).** 사용자 선택.
- **항목 편집은 「그 항목만 바꾼 문서 전체」를 draft에 둔다. 쓰기 직전 바탕 원문과 다르면 충돌로 둔다.** 기존 충돌 판정이 그대로 걸리고, 낡은 바탕으로 로컬 변경을 덮지 않는다.
- **등록 안 된 프로젝트 지침은 처음 고칠 때 지침 문서로 자동 등록한다.** 버전·충돌 처리가 등록 문서에 붙는다.
- **프로젝트 밖(전역·상위·기억·Codex) 파일은 등록하지 않고 파일 그대로 쓰며, 버전 사본은 이 Mac에만(TRK-41).** 개인 지침·기억을 iCloud로 올리지 않는다. 디스크가 바뀌었으면 쓰지 않고 「다시 읽기」.
- **기억 지우기 같은 여러 파일 변경은 한 묶음으로 확인하고 쓴다.** 반쪽만 쓰지 않는다.
- **Codex 규칙 파일은 임시 `CODEX_HOME`으로 Codex CLI 검사를 통과해야 저장한다. 검사 못 하면 저장하지 않는다.** 자체 검사를 지나도 Codex가 못 읽는 줄이 있을 수 있다. 되돌리기·복원은 검사하지 않는다.
- **관리 정책 `CLAUDE.md`는 보기만. 스킬은 목록에 넣지 않는다.**

## 재개 (TRK-12, 10-01)

- **목표·남은 조건·미검증 요약은 재개 창에만.** 카드 상세에는 이미 본문·조건·근거가 있다.

- **실행 파일은 흔한 설치 폴더 → 앱 PATH 순으로 찾는다. 로그인 셸을 띄우지 않는다.** 셸은 사용자 설정을 실행하고 느리다.
- **도구는 인자 없이 실행하고 문맥은 클립보드로만.** 인자는 셸 기록·프로세스 목록에 남는다.

## 자동 갱신 빈틈·프로젝트 상황 (TRK-62·63, 10-02)

## 원격·컨테이너 세션 (TRK-53, 10-03)

- **SSH 원격·개발 컨테이너만 지원한다. 웹·클라우드 세션은 보류.** Mac 앱에 닿을 길이 따로 필요하고 방식은 사용자 결정 대기.
- **앱 서버는 계속 127.0.0.1만. 스크립트는 `WAYPOINT_URL`로 보낸다.** 컨테이너는 `host.docker.internal`이 루프백에 닿고 SSH는 터널을 쓴다.
- **원격 세션은 같은 git origin의 등록 프로젝트에 잇는다. 서로 다른 로컬 작업 트리 둘 이상이면 잇지 않는다.** 원격 경로는 Mac 경로와 다르지만 원격 주소는 같다. (경로 대응 표: 사용자가 등록해야 한다)
- **원격 모드는 `WAYPOINT_REMOTE`, 없으면 `WAYPOINT_URL`이 있거나 macOS가 아닐 때. Mac 로컬 payload·outbox는 그대로.** 로컬에 원격 정보를 붙이면 미등록 클론이 등록 프로젝트에 이어진다.
- **이은 훅은 처리 전에 경로를 로컬 작업 트리로 옮긴다. 원격 파일의 체크아웃은 `<host>:<경로>`.** 기존 매칭을 그대로 쓰고, Mac과 원격의 같은 파일을 같은 작업 트리로 오인하지 않는다.
- **원격 outbox는 훅이 앱에 닿을 때 뒤에서 상한 있게 보낸다. 앱은 `replay/`에 받아 두고 0.1초씩 실시간 경로로 처리한다.** 그 자리에서 흡수하면 메인 액터를 오래 잡아 로컬 블록을 잃었다.
- **replay가 남은 동안 블록이 필요 없는 훅은 뒤에 세우고, 이른 훅이 늦게 오면 세션 시작을 당긴다.** 다시 이어진 뒤 첫 훅이 쌓인 줄보다 먼저 온다.
- **`remote-setup.sh`는 앱 설치기 명령행(`waypoint-integration`)으로 원격 설정을 고친다.** 병합 규칙을 두 벌 두지 않는다.
